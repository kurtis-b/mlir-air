# Measurement probes

One-off tools that produced the measurements load-bearing specs in
`docs/plans/transformer-layer-execution-studies/` rest on. **Not tests** — nothing runs them in CI,
and they are kept so a later session can re-derive a claim instead of trusting prose.

Run from the repo root with the toolchain on PATH:

```bash
. agents/scripts/port-loop/lib-env.sh && pl_env_ensure   # needs a log_error shim if run bare
python3 agents/probes/<probe>.py
```

| `probe_context_reuse.py` | **`_evict_context`'s corruption is one CELL, not a class — and the ABI `offload`'s next phase needs is a clean one.** A 2×2 on `q_proj` 1024×768×768, four executions of one artifact on one input pair: `elf`+`[2,2]` diverges from its own run 1 by **3.8141e-01** (replicated 2/2), while `elf`+`[1,1]`, `xclbin`+`[2,2]` and `xclbin`+`[1,1]` are all bit-identical 4/4. | `probe_one_xclbin_n_streams.py` | **N instruction streams under one xclbin WORKS, and needs THREE distinct identifiers per stream.** Two GEMMs of different shape chained with `--xclbin-input` both execute correctly from one `hw_context`, either compile order. `kernel_name` (a duplicate makes xclbinutil REFUSE the merge — the only loud one), `instance_name` (the loader matches by substring, `xrt.py:634`), `kernel_id` (the merged `AIE_PARTITION` routes to a PDI by `dpu_kernel_ids`; every AIR compile defaults to `0x901`). Both-directions control on the id: collide it and the second kernel times out at one shape, returns **garbage at `mean_rel_L1` 1.41 with no error raised** at the other. The `insts.bin` is byte-identical either way, so the instruction stream is a red herring and the discriminating field needs `xclbinutil --dump-section AIE_PARTITION:JSON`. **This probe sets `kernel_name` and `instance_name` to one string**, so it never exercised the first alone; the third identifier surfaced only when a five-shape mode was built on it. | [29](../../docs/plans/transformer-layer-execution-studies/29-offload-n-streams.md) |

| `probe_fused_resident_tail.py` | **The closest resident tail the existing builders admit, measured at pass-dump altitude.** Stitches J7a's norm-tail pipeline (×2) + J7b's accumulator-ring FFN into one module and compiles through the production aircc (`debug_ir=True`, hermetic — no NPU, no kernel objects, ~4 s/shape). At 1024×768 and 4096×768: each segment gets its **own `aie.device`** (stitch-level composition is time-multiplexed at segment granularity), 32 core→core flows (both pipelines' stage edges survive the stitch), exactly 2 shim inbound per column on the nt segments, 0 packet-typed channels, and **15–16 channel symbols through `air-fuse-channels` in ~4 s** against the >1200 s wall at 90. Two walls it measures rather than hides: the FFN slice only builds as a **64-row band** (memtile feed-port cap), and at 4096 the **mirror hand-off is ill-typed by construction** (mirror writes plane-major, only row-interleaved packs build there). Negative control: `--herd-x 4` — placement collapses and the core→core check fires. | [31](../../docs/plans/transformer-layer-execution-studies/31-fused-resident-tail.md) · [31a](../../docs/plans/transformer-layer-execution-studies/31a-resident-byte-floor.md) |

| `probe_ffn_resident_interior.py` | **Doc 31 R1's open structural questions, answered on the one-segment builder** (`builders/ffn_resident.py`), hermetic at pass-dump altitude (~1 s): ONE tile-bearing `aie.device` (the resident claim the stitched probe measured as three); core→core flows exactly `herd_x` (up→GeLU; every other hand-off memtile-mediated by port arithmetic); **shim MM2S 7 of 16 ports, worst column 2** (`[2026-08-12]` clause F widened with the gate's, queue item 10 — it read "1/column" while counting `shim→core` circuit flows only, and an L2-staged refill is a `shim→memtile` flow on the same port); 0 packet channels; the down ring's 4 → 2 hoist inside the composition; **12 channel symbols through `air-fuse-channels` in ~1 s**; L2 staging spread across two memtiles' columns by the allocator itself; NOTHING ping-ponged (up core 40 KiB of 64 — the predicted 81 KiB pp overflow does not happen). Found and priced one wall: a **textually-unrolled segment-scope `dma_memcpy_nd` becomes its own auto channel per instance**, and 24 of them left `air-isolate-async-dma-loop-nests` non-terminating past 25 minutes on a 692-line module — the reason the down feed Python-unrolls ONLY the sub-channel index (H5) and loops everything else. Carries a 600 s compile alarm so a recurrence reports instead of wedging the build queue. | [31](../../docs/plans/transformer-layer-execution-studies/31-fused-resident-tail.md) |

| `probe_fuse_channels_sibling_nests.py` | **`air-fuse-channels` crashes on ≥3 sibling same-bounds channel nests, and the boundary is measured: 2 fuse cleanly (5/5), 3 SEGV (5/5).** Stack: `air::isAsyncOp` ← `AIRFuseChannels::runOnFunction` (the NFL merge path — `nfl_erased_ops` queried after `wrapRegionsWithForLoops` invalidated them; a use-after-free profile). Under aircc the same module is an ASLR coin toss — R1's 284-line module compiled clean twice then crashed twice, byte-identical input. The trigger is forced, not exotic: H5 keeps sub-channel indices literal, so a per-column fan-out MUST textually unroll, and each textual segment-scope `dma_memcpy_nd` becomes its own auto channel — herd_x=4 gives 4 mutually-mergeable siblings. The reproducer is a ~40-line builder / 115-line pre-fuse IR: `--nests 3 --keep out.mlir`, then `air-opt --air-fuse-channels out.mlir`. Blocks every R1 gate arm; reported, not fixed in-phase. | [31 §R1 status](../../docs/plans/transformer-layer-execution-studies/31-fused-resident-tail.md) |

| `probe_r1_arrival_map.py` | **R1's deterministic wrong answer is ONE truncated transfer, not a wall.** Decomposes a `probe_r1_rung.py --dump-npz` output into one coefficient per (down-K step, 8-row run) of the H chunk that step consumed — 1.00 = that run arrived, 0.00 = it did not, no matrix inversion so no cond(w_down) noise. Reads **the last chunk of every up-herd group arriving as its first run with the other seven zeroed**, at every rung with `chunks_per_group > 1`, and clean 1.00s wherever `chunks_per_group == 1`. Cause: `air-to-aie`'s shared-staging-buffer lock placement puts the acquire at each put, so nothing guards the core's accumulator memset at the top of the next round and it overtakes the last chunk's in-flight BD. Carries its own controls — a passing rung must read all 1.00, and a wrong `--seed` is REFUSED rather than scored. | [49](../../docs/plans/transformer-layer-execution-studies/49-r1-deterministic-defect.md) |

| `probe_r2_order_seam.py` | **Doc 31's seam 2 resolves by re-mapping the FFN interior to a ROW partition, not the norm tail** — a norm can only emit whole rows and a GEMM's A operand is a blocked column strip of all of them, so no row→tile re-mapping converts one to the other. Row-partitioned, producer core c and consumer core c own the same rows, and the retile becomes LOCAL to one core — compute, not a BD. Design arm `row_tiles`: routed in 0.5 s, 4 core→core flows (one L1→L1 edge per column), 0 packet channels, **every `aie.dma_bd` offset 0** (nothing addresses a staged buffer at all), worst core L1 44,032 B of 65,536, nothing ping-ponged. **Three controls, all verified failing, each a different wall**: `row_band` — the obvious literal-offset L1 band is a **SILENT MISCOMPILE**, `air-shrink-memref-sizes-by-access` (pass 029) rewrites `memref<12288xbf16,2>` → `<3072>` and leaves the gets at 3072/6144/9216 and the retile reading to element 12,256, no error and no warning; `l2_staged` — doc 31's own "stage bands in L2" candidate never reaches the frozen-BD question, refusing at `'aie.memtile_dma' op has more than 48 blocks` (the memtile analogue of wall 4, `getNumBDs(MemTile)` = 48 vs the shim's 16), which also prices the unroll-the-feed dodge at 96 BDs; `--wloop nested` — a **NEW compiler abort**, `tileChannelOpByFactor` composes with a two-symbol L3-side `affine.apply` but builds `AffineMap::get(0, 1, add)`, tripping `willBeValidAffineMap` in `AIRSplitL2MemrefForBufferConstraintPass`. The dodge is exact, not a workaround: the refill address is linear in `g*k_steps + k`, so one flattened loop gives a one-symbol map, same transfers in the same order, and compiles (21 dumps + abort → 59 dumps routed). | [31b](../../docs/plans/transformer-layer-execution-studies/31b-r2-order-seam.md) |

Not a violation on R1; a blind spot exactly where R2 adds streams. **`[2026-08-12]` FIXED (queue item 10)**: both the gate and clause F now count per-column MM2S demand over both flow kinds **and over packet flows** — over budget AIR emits packet flows sharing one queue, so a port count reads 0 on an over-budget column — and the gate carries the negative control. **Why `probe_accum_hoist.py` and `probe_accum_aircc.py` both exist.** `air-opt` with a hand-built
pass list answers *"does this pass fire"*; it does not answer *"does this compile"*. The two diverge
wherever a later pass rewrites what was measured — `air-to-aie` normalizing external callee
signatures is the case that cost this plan a spec claim. Match the probe's altitude to the claim.

**Why `probe_backend_preset_hardware.py` and `probe_context_reuse.py` both exist.** They are the
same knob caught doing two different things. The first says `[2,2]` HANGS FlashAttention at 4096;
the second says `[2,2]` leaves context-corrupting residue in a plain projection GEMM under the ELF
ABI. Neither subsumes the other, and a fix that addressed only one would leave the other live.
